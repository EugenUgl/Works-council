# Конфигурация и страница настроек

  Предварительно: [`architecture.md`](architecture.md)

## Главное правило

  **Каждое поле `Config` обязано быть `.volatile()`.**

Хост принимает правку формы только для поля, путь к которому проходит
проверку `isVolatilePath` (обход схемы через `schema.dict[key]` и проверка
`meta.volatile`). Иначе **вся** мутация отвергается с
`Config field "<key " is not volatile`, даже если правилось другое поле.

Проверка: [`test/schema.test.mjs`](../test/schema.test.mjs) — повторяет обход
хоста на схеме плагина. Добавили поле без `.volatile()` — тест падает.

## Где живёт конфигурация

| Место | Роль |
|---|---|
| [`index.js`](../index.js) → `Config` | Схема, значения по умолчанию, описания |
| [`cordis.patch.yml`](../cordis.patch.yml) | Строка `delegate-io` — значения, с которыми плагин установлен |
| [`client.js`](../client.js) → `DEFAULTS` | Зеркало схемы для формы и для вычисления «грязных» полей |
| Профиль `~/.dsh/profiles/desktop` | Хранит сохранённые значения (правится только через GUI/remote API) |

**Синхронность обязательна.** Новое поле = четыре правки: `Config`,
`cordis.patch.yml`, `DEFAULTS` в `client.js`, тест/документация.

## Справочник полей

### По типу задачи — `<task ` ∈ `read` | `web` | `write` | `think`

| Поле | Тип / по умолчанию | Смысл |
|---|---|---|
| `<task Enabled` | bool; `true` (у `think` — `false`) | Делегировать ли этот тип задачи |
| `<task Provider` | string `''` | Провайдер воркера; пусто — наследовать основной агент |
| `<task Model` | string `''` | Модель воркера; пусто — наследовать |
| `<task ReasoningEffort` | string; `''` (`think` — `'high'`) | Усилие рассуждений; пусто — по умолчанию модели |
| `<task MaxContextTokens` | int; `0` | Компакция воркера после стольких токенов; `0` — без лимита |

Про `think`:

| Поле | Тип / по умолчанию | Смысл |
|---|---|---|
| `thinkMaxTurns` | int ≥ 0; `2` | Сколько раундов уточнений мыслитель может запросить |
| `thinkEscalateAfter` | int ≥ 0; `2` | После стольких сбоев подряд подсказывать `delegate_think`; `0` — выключено |

`thinkReasoningEffort: 'high'` — намеренно: мыслитель существует как раз
заменой маршрута без рассуждений, наследовать «пусто» бессмысленно.

### Делегирование целиком

| Поле | Тип / по умолчанию | Смысл |
|---|---|---|
| `subagentProvider` | string `'spawn'` | Бэкенд субагентов, в котором живут воркеры |
| `requestTimeoutMs` | int; `900000` | Сколько основной агент ждёт один делегированный вызов |
| `fallbackToDirect` | bool `true` | При сбое воркера выполнить инструмент напрямую |
| `maxJobsPerWorker` | int ≥ 1; `25` | ⚠️ **Не влияет на жизнь воркера** (см. долг ниже) |
| `workerIdleMs` | int ≥ 0; `600000` | ⚠️ **Не влияет на жизнь воркера** (см. долг ниже) |

  ⚠️ **Технический долг.** `maxJobsPerWorker` и `workerIdleMs` остаются в
  схеме `Config`, в `cordis.patch.yml` и в форме настроек, но жизненным
  циклом воркера больше не управляют: заменяют его только лимит
  контекста (`<task MaxContextTokens`). См.
  [`decisions.md`](decisions.md) → D15 и
  [`development.md`](development.md#технический-долг).

### Результат

| Поле | Тип / по умолчанию | Смысл |
|---|---|---|
| `maxResultChars` | int ≥ 0; `12000` | Бюджет результата; `0` — отдавать целиком |
| `budgetStrategy` | `spill` \| `summary`; `spill` | Что делать сверх бюджета |
| `verifyWrites` | bool `true` | Проверять `write`/`edit` по файлу на диске |
| `inspectEnabled` | bool `true` | Открывать `delegate_inspect` |
| `inspectMaxChars` | int ≥ 0; `4000` | Бюджет отчёта `delegate_inspect` |
| `depthBudget` | `overview` \| `normal` \| `thorough`; `normal` | Строк дословных сниппетов: 25 / 40 / 80 |

## Как читаются значения

`valueOf(ref, fallback)` — [`index.js:140`](../index.js) — распознаёт и
volatile-ссылку (объект с `get()`), и обычное значение. Поверх —
`textOf` (обрезка строк), `Number(...)` с проверкой `Number.isFinite` и
границ. Все аксессоры (`routeFor`, `timeoutMs`, `maxResultChars`, …) —
**чистые функции чтения, без кэша**, поэтому правка из GUI действует на
следующем вызове.

### Что меняется на лету, а что нет

| Меняется сразу | Требует перезагрузки плагина |
|---|---|
| `*Enabled`, все маршруты, лимиты, бюджет, `verifyWrites`, `inspectEnabled`, `thinkMaxTurns`, `thinkEscalateAfter` | `subagentProvider` — читается при создании сессии; действует на следующую сессию воркера |

**Размер пула воркеров — не поле конфига.** Сколько сессий обслуживает задачу
(`read`/`web`/`write` — по три, `think` — одна), задаёт константа
`WORKERS_PER_TASK` в [`index.js`](../index.js), а не `Config`: строка
`cordis.patch.yml` и форма настроек от пула не меняются. Все слоты пула читают
настройки задачи из тех же полей `<task>Provider`/`<task>Model`/
`<task>ReasoningEffort`/`<task>MaxContextTokens`, поэтому «настройка задачи»
автоматически действует на весь пул. См.
[`decisions.md`](decisions.md) → D25.

## Страница настроек (`client.js`)

### Две вкладки

Страница состоит из переключателя (`role="tablist"`) и двух панелей
(`role="tabpanel"`):

| Вкладка | Что показывает |
|---|---|
| «README» (`tabReadme`) — **первая** | `README.md` пакета, отрисованный по подмножеству markdown |
| «Настройки» (`tabSettings`) | Секции `read`/`web`/`write`/`think`, блок «Делегирование», кнопка сохранения |

- Активная вкладка хранится в состоянии `Card` (`useState('readme')`),
  поэтому переключение **не теряет** несохранённые правки формы и введённый
  текст подсказок: `draft`, `busy`, `notice` живут в `Card`, а не в панели.
- **README открыт первым.** Страницу плагина открывают, чтобы понять, что это
  такое, а не чтобы сразу править лимиты; справочник отвечает на первый
  вопрос, настройки — на второй.
- **Ни одна панель не рисует заголовка и описания.** Над карточкой хост уже
  показал название и описание строки из `locale/*.json`. Свой заголовок
  «Модели воркеров» с абзацем-описанием дублировал их двумя строками ниже
  (см. [`decisions.md`](decisions.md) → D20). Панель README начинается с
  собственного `#`-заголовка README; панель настроек — сразу с секций.
- У `tablist` остался `aria-label` (`tabsLabel`): видимого заголовка у
  карточки нет, но доступное имя у переключателя быть должно.
- **`summary`-вид обязан быть пустым (`return null`).** Хост вызывает
  `plugins.row.config` на странице строки **дважды**: `summary` — в строке
  описания (`.detailDesc`), `page` — в секции конфигурации
  (`[data-plugin-config]`). Вкладки живут в `page`; всё, что вернёт `summary`,
  окажется над ними. Возврат разметки даёт второй переключатель вкладок под
  README (см. [`decisions.md`](decisions.md) → D22).
- Текст README **впечатан в сам [`client.js`](../client.js)** — в блок между
  маркерами `// README-НАЧАЛО` и `// README-КОНЕЦ`. Блок генерируется из
  [`README.md`](../README.md) скриптом
  [`scripts/build-readme.mjs`](../scripts/build-readme.mjs)
  (`npm run build:readme`); `npm test` сверяет его с исходником и падает, если
  он устарел.
- **Из копии вырезаны разделы для разработчика**: «Правило проекта»,
  «Быстрый старт», «Структура репозитория». Вкладка открыта первой и читается
  человеком, который настраивает плагин; команды запуска тестов и дерево
  каталогов для него ложны (запускать в GUI нечего) и превращают справку в
  гору текста, которую не станут прокручивать. Вырезает
  `withoutDeveloperSections` по заголовку раздела; остальные разделы
  («Зачем это нужно», «Что перехватывается», «Главные понятия», «Известные
  ограничения») остаются, и тест проверяет обе стороны — и отсутствие
  вырезанных, и наличие содержательных.
- **`client.js` не имеет права требовать ничего, кроме платформенных
  модулей.** Загрузчик web-бандла резолвит только `react`; на любой другой
  идентификатор он отказывает (`require("...") missed the module table`), и
  падает весь запуск DSH, а не одна вкладка. Именно на этом упало приложение,
  когда README жил отдельным модулем `readme.js` (см.
  [`decisions.md`](decisions.md) → D19). Поэтому встраивание в тот же файл, а
  не импорт: соседний файл в бандл всё равно не попадёт.
- Markdown отрисован вручную подмножеством: заголовки `#`..`###`, списки,
  ограждённые блоки, таблицы, инлайн-код, **жирный**, ссылки. Новая
  markdown-зависимость ради одной вкладки не добавлялась. Относительные
  ссылки README показываются как текст с подсказкой `title`: файлов
  репозитория в GUI нет, и переход вёл бы в никуда.

### Слоты

Регистрируется в двух местах, одна и та же карточка:

- `plugins.bundle.config` с ключом `BUNDLE_NAME` — страница bundle в списке плагинов;
- `plugins.row.config` с ключом `ROW_KEY = "<package #delegate-io"` — страница строки.

Локаль `delegateIo` регистрируется через `ctx.locale.register`; словари
`en`/`ru` заданы прямо в `client.js` (в отличие от `locale/*.json`, которые
описывают только заголовок строки).

### Шапка страницы — данные хоста, а не наш слот

Название и описание над карточкой рисует **сам DSH**: `plugins.row.config`
получает только `view: 'page'` и `view: 'summary'`, а заголовок, хлебную
крошку и абзац описания выводит компонент хоста `RowDetail`. Источник —
`locale/*.json` → `meta.title` / `meta.description`, прочитанные из пакета
**без активации плагина**; иконка — из экспорта `./icon`.

Отсюда следствия, которые надо знать, прежде чем «убирать заголовок»:

| Что в `locale/*.json` | Что на странице |
|---|---|
| `meta.description` есть | Абзац описания над вкладками — то самое дублирование (D20) |
| `meta.description` отсутствует | `<p>` рендерится **пустым** — описания нет |
| `meta.description: ""` | **Ошибка**: `textOf` требует непустую строку, метаданные ломаются |
| `meta.title` отсутствует | Подставляется **имя пакета** `@local/dsh-plugin-delegate-io` |
| `meta.title: ""` | **Ошибка**: `textOf` требует непустую строку |

**Заголовок страницы убрать нельзя — и это предел слота, а не недоработка.**
Хост рендерит `<h3 class="…detailTitle">{rowTitle}</h3>` безусловно, вне
слота, а `rowTitle` — это `meta.title` либо, при его отсутствии,
`moduleShortName(row.moduleName)`. Убрать текст из заголовка означает либо
оставить пустую строку (её отвергает `textOf`), либо показать имя модуля
`dsh-plugin-delegate-io`. Единственный управляемый рычаг — **каким** будет
заголовок: поэтому он сокращён до «Делегирование IO» / «Delegate IO», а не
устранён. Описание убирается полностью, потому что при отсутствии
`meta.description` хост рендерит пустой `<p>`.

> ⚠️ Всё это касается только **отображения**. Разметкой шапки (заголовок,
> хлебная крошка, строка описания) слот не управляет: она рендерится хостом
> до и вокруг нашего вывода.

**`package.json`.`description` — ловушка.** При отсутствии
`meta.description` хост подставляет описание манифеста
(`localizedText(..., fallbackText(manifest?.description), '')`), и абзац
возвращается на страницу — уже по-английски. Поэтому поле убрано и из
`package.json`; `test/readme-tabs.test.mjs` проверяет оба места.

### Источник данных и сохранение

1. **Чтение.** `formScopeOf(ctx)` берёт `ctx.get('configForms').get('delegate-io')`
   — снимок значений + `subscribe`.
2. **Модели.** `remote.session.modelCatalog()` — каталог провайдеров и моделей
   с их `reasoning.efforts`. Недоступен → форма переходит на ручной ввод.
3. **Сохранение.** `remote.settings.describe()` → найти `ns === 'delegate-io'`
   → `remote.settings.mutate(NAMESPACE, ops, revision)`.
4. **Только изменённые поля.** `ops` собираются фильтром
   `draft[key] !== lastSource.current[key]`. Ненайденное хостом поле не ломает
   всю мутацию.
5. **Обратное чтение.** После успеха — повторный `describe()`; форма
   **принимает значения хоста**, а если они отличаются от введённых, пишет
   «сохранено, применится после перезагрузки».

Сохранение только изменённых полей и обратное чтение — это два
регрессионных фикса, см. [`decisions.md`](decisions.md).

### Поведение формы

- Провайдер и модель — **пара**: установлены оба или ни одного. Иначе
  показывается `pairHint`.
- Смена провайдера пытается **сохранить модель**, если она есть у нового
  провайдера; иначе очищает.
- `editCount` не принимает пустое/отрицательное/нечисловое — держит последнее
  валидное значение.
- Поля типа задачи блокируются, когда задача выключена.
- Значение, которого нет в каталоге, всё равно предлагается как опция
  `saved-…` — сохранённая настройка не должна «теряться».
- `CardBoundary` превращает ошибку рендера в текст
  `delegate-io page error: …`, а не в пустой слот.

## Как добавить новое поле (чек-лист)

1. `docs/configuration.md` — описать поле (документация первая!).
2. `index.js` → `Config`: `z.<type ().default(<v ).volatile().description('…')`.
3. `index.js` → аксессор рядом с остальными + `Number.isFinite`-защита.
4. Прочитать значение через аксессор там, где оно нужно (не напрямую).
5. `cordis.patch.yml` — добавить значение в строку.
6. `client.js` → `DEFAULTS` и, если нужно, контрол в форме.
7. `test/` — тест на поведение и прогон `schema.test.mjs`.
8. `delegate_io_status` — вывести поле, если оно диагностически полезно.

## На что легко сломать

- **Забыть `.volatile()`** — форма перестанет сохраняться **целиком**.
- **Добавить поле в `Config` и забыть `DEFAULTS`** — форма не увидит поле,
  а «грязность» посчитается неверно.
- **Добавить в `cordis.patch.yml` поле, которого нет в `Config`** — хост
  отвергнет строку.
- **Кэшировать значения конфига** — «живое» переключение перестанет работать.
- **Передавать `ops` со всеми полями** — старый хост отвергнет неизвестный ключ.

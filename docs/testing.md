# Тестирование

> Предварительно: [`architecture.md`](architecture.md), [`decisions.md`](decisions.md)

## Философия

Тесты — **регрессионные маркеры**, а не «покрытие». Каждый хитрый баг оставлен
в шапке своего теста комментарием: что сломалось, почему и как это ловится.
Прежде чем менять поведение, прочитайте шапку соответствующего теста — она
часто объясняет, почему «очевидное» решение неверно.

Тесты **полностью офлайн**: `apply()` запускается на самописном стаб-контексте
Cordis, реальный DSH и сеть не нужны. Поэтому их можно гонять где угодно с Node.

## Запуск

`package.json` → `scripts.test` — цепочка через `&&`, порядок имеет значение:

```
readme-tabs → schema → prestep → live-enable → result → inspect → think → probe
→ context-limit → worker-lifetime
```

```powershell
# нет node в PATH — берём из runtime DSH
$node = 'D:\Soft\DeepSeek\resources\runtime\primary-runtime\dependencies\node\bin\node.exe'
& $node test/schema.test.mjs
```

Каждый файл — самостоятельный скрипт с `assert`; упавший бросает, и цепочка
обрывается на нём.

## Устройство стаб-харнесса

Все харнессы устроены однотипно, поэтому новый тест пишется копированием
соседнего:

```js
function harness(config) {
  const handlers = new Map();       // ctx.on(...) → запомнили, можно вызвать вручную
  const globalTools = new Map();    // ctx.tools.register на корне
  const rootTools = new Map();
  const files = new Map();          // in-memory fs
  const spills = [];                // что ушло в spillStore
  const script = [];                // «сценарий» воркера: какие события он пошлёт
  const ctx = {
    on: (name, fn) => { handlers.set(name, fn); },
    get: (name) => services[name],
    tools: { register, get },
    subagents: { startActivation, sendMessage, interrupt, drainChildren },
    agents: { list, get },
    logger: { warn, info },
  };
  // корневой агент, настоящие инструменты `read`/`write`/`edit`
  apply(ctx, config);
  return { ctx, handlers, files, spills, script, calls, root };
}
```

Ключевые приёмы:

- **Скрипт воркера.** `script.push(...)` описывает, что воркер «сделает»:
  вызвать `tool/result`, ответить `assistant/message` или ничего. Харнесс
  отдаёт эти события в `session/event`.
- **Мутабельный конфиг.** `live-enable` держит объект и меняет в нём поле —
  ровно то, что делает volatile-ссылка в живом хосте.
- **Ручной вызов хуков.** `handlers.get('agent/pre-step')(payload, next)`
  позволяет подать любой батч сообщений.

## Как добавить тест

1. **Сначала документация**: описать новое поведение на профильной странице.
2. Создать `test/<область>.test.mjs` по образцу ближайшего.
3. Проверить ровно то, что сломалось/добавилось — не «всё сразу».
4. Добавить файл в `scripts.test` в `package.json` **в логическое место**
   цепочки.
5. Добавить строку в таблицу выше и, если есть регрессия, — запись в
   [`decisions.md`](decisions.md).

## Чего тесты не проверяют

- Реальный `ctx.subagents` и настоящие сессии — это делает `probe.test.mjs`
  как зонд, но не как гарантию.
- GUI-рендер формы (`client.js`) — тестов нет; `readme-tabs.test.mjs` проверяет
  только наличие маркеров вкладок в исходнике, свежесть встроенного блока
  README и отсутствие неплатформенных `require`, а сам рендер — нет.
- **Загрузку клиента бандлом** — никакой офлайн-тест её не проверяет. Зелёные
  `node --check` и маркеры возможны на коде, который загрузчик отвергнет и
  уронит весь запуск DSH (так было в D19). После правки `client.js` нужен
  реальный старт приложения.
- Поведение компакции на реальном бэкенде.

Поэтому после правок, затрагивающих реальные сервисы, нужна ручная проверка в
графическом интерфейсе.

## На что легко сломать

- **Убрать файл из `scripts.test`** — тест останется, но не станет выполняться.
- **Править `README.md`, не пересобрав блок в `client.js`** — падает
  `readme-tabs.test.mjs`; лечится `npm run build:readme`.
- **Добавить в `client.js` любой `require`/импорт, кроме `react`** — падает
  `readme-tabs.test.mjs`; в GUI это кончилось бы незапускающимся DSH (D19).
- **Вернуть карточке свой заголовок или описание** — падает
  `readme-tabs.test.mjs`: на странице строки они дублируют заголовок хоста
  из `locale/*.json` (D20).
- **Поменять вкладки местами** — падает `readme-tabs.test.mjs`: проверка идёт
  по порядку объявления в `tablist`, а не по наличию маркеров.
- **Вернуть `meta.description` или `package.json`.`description`** — падает
  `readme-tabs.test.mjs`: описание снова появится над вкладками (D21).
- **Вернуть текст в `view: 'summary'`** — падает `readme-tabs.test.mjs`: хост
  зовёт слот дважды, и на странице появляется вторая полоса вкладок (D22).
- **Поставить `meta.description: ""`** — не тест, а хост: `textOf` требует
  непустую строку и роняет чтение метаданных. Поле должно отсутствовать.
- **Пытаться убрать `<h3>` через `meta.title`** — бесполезно: без `title`
  хост подставит имя модуля, а `""` и `" "` отвергает `textOf` (`trim()`).
  См. D23.
- **Добавить раздел для разработчика в README** — попадёт на вкладку, пока
  не дописан в `withoutDeveloperSections`; падает
  `readme-tabs.test.mjs` (D24).
- **Ослабить `schema.test.mjs`** — вернуться к «падает вся форма».
- **Сделать тест зависимым от реальной сети/DSH** — теряется возможность
  гонять офлайн.

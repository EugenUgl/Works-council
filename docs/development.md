# Разработка: процесс, выпуск, долги

> Предварительно: [`testing.md`](testing.md), [`configuration.md`](configuration.md), [`decisions.md`](decisions.md)

## Рабочий процесс (правило проекта)

1. **Прочитать документацию** — [`README.md`](README.md), затем профильную страницу
   из таблицы. Если документация расходится с кодом — сначала поправить её.
2. Сформулировать изменение и **какой инвариант** оно затрагивает
   ([`architecture.md`](architecture.md) → «Инварианты»).
3. Внести изменение минимальным диффом (без попутного реформата).
4. Добавить/обновить тест, прогнать `scripts.test`.
5. Обновить документацию: профильная страница + [`decisions.md`](decisions.md),
   если решение архитектурное.
6. Проверить в GUI, если затронуты реальные сервисы (воркеры, форма, слоты).

## Чек-лист правки

- [ ] Прочитана документация по затронутой области.
- [ ] Новые поля `Config` объявлены `.volatile()` и есть в
      `cordis.patch.yml` + `DEFAULTS` (`client.js`).
- [ ] Значения конфига читаются через аксессоры (`textOf`/`Number`), не напрямую.
- [ ] Не нарушен ни один инвариант из `architecture.md`.
- [ ] Любой новый путь отказа **логируется** и деградирует явно.
- [ ] Добавлен тест: новый файл и `scripts.test`, либо расширен существующий.
- [ ] Обновлены профильная страница документации и карта в `docs/README.md`.
- [ ] Приложение **перезапущено целиком** (см. «Перезагрузка после правки»),
      а не только строка плагина.
- [ ] Красивая, но не обязательная косметика отложена (см. «Техдолг»).

## Локальный цикл

```powershell
$node = 'D:\Soft\DeepSeek\resources\runtime\primary-runtime\dependencies\node\bin\node.exe'

# один тест
& $node test/schema.test.mjs

# вся цепочка — как в package.json → scripts.test
& $node test/schema.test.mjs; if ($?) { & $node test/prestep.test.mjs }
# …удобнее писать скрипт, повторяющий цепочку
```

Плагин подключён в профиль через `link:` — правки `index.js`/`client.js`
применяются после перезагрузки плагина в DSH (для клиента — ещё и после
обновления web-бандла, если он собирается отдельно).

### Вкладка README

Текст вкладки «README» — блок в самом `client.js` между маркерами
`// README-НАЧАЛО` и `// README-КОНЕЦ`. Порядок:

1. Правится `README.md`.
2. `npm run build:readme` — пересобирает блок в `client.js`.
3. `npm test` — `readme-tabs.test.mjs` первым шагом падает, если блок устарел.

Рукописной правки блока нет: она будет перезаписана. Отдельного модуля
`readme.js` больше не существует — на `require('./readme.js')` загрузчик
бандла отказал и уронил запуск DSH (см. [`decisions.md`](decisions.md) → D19).

> ⚠️ **У `client.js` есть ограничение, которое не видно тестам исходника.**
> Загрузчик web-бандла резолвит только платформенные модули (`react`). Любой
> другой `require`/импорт — краш запуска приложения целиком, а не одной
> вкладки. Тест `readme-tabs.test.mjs` ловит неплатформенные `require`, но
> **сам факт загрузки клиента** проверяется только реальным стартом DSH:
> `node --check` и маркеры в исходнике зелёные и на неработающем коде.

## Перезагрузка после правки — отдельная процедура

> **Переключение строки плагина в GUI не гарантирует перезагрузку модуля.**

`dsh-app-boot` прямо документирует: публикация резолва профиля «не выгружает
модули и не очищает кеш Node», а загруженные модули не перезагружаются;
`dsh-hmr` заменяет только те модули, чьё изменение он может доказать, а
модули хоста требуют перезапуска. Поэтому после правки `index.js`:

1. **Перезапустить приложение целиком**, а не только строку в профиле.
2. Убедиться, что живёт новый код: `delegate_io_status` → `tools` показывает
   `registered`/`visible` для `delegate_think`/`delegate_inspect`/
   `delegate_io_status`; `settings.ours` содержит `delegate-io`.
3. Сравнить `Get-Process | Select StartTime` процесса DSH с
   `LastWriteTime` у `index.js`: процесс обязан быть **новее** файла.

### Транзиторное окно при включении/выключении строки

При toggle строки между «выключено» и «включено» инструменты на несколько
десятков секунд пропадают из набора: в журнале сессии это видно как
`developer/message` с `tool-removal` и заголовок запроса с меньшим числом
инструментов, хотя галочки в форме остаются отмеченными. Наблюдение
«инструмент не подключился», сделанное в этом окне, — ложное. Проверка:
последний `request/header` в журнале сессии должен снова содержать нужный
инструмент.

### Как проверить факт, а не ощущение

Модель не видит свой список инструментов, поэтому утверждение «инструмента
нет» изнутри сессии — гипотеза, пока не проверено:

- `delegate_io_status` → `tools` (регистрация и видимость по каждому);
- последний `request/header` журнала сессии: `data.header.tools`;
- `dsh-llm` при возобновлённой сессии складывает объявления из истории —
  пропуск `tool-addition` в `developer/message` может дать расхождение между
  заголовком и фактическим запросом.

## Выпуск версии

1. Обновить `"version"` в [`package.json`](../package.json).
2. Прогнать все тесты.
3. Проверить, что `files` содержит всё нужное:
   `index.js`, `client.js`, `scripts/build-readme.mjs`, `cordis.patch.yml`,
   `locale/*.json`, `icon.svg`.
   **`docs/` и `AGENTS.md` в список поставки не входят** — это внутренняя
   документация. Если её нужно поставлять, добавить явно.
4. Перед первым шагом `npm test` пересобрать вкладку README, если менялся
   `README.md`: `npm run build:readme` (иначе `readme-tabs.test.mjs` упадёт).
   Генератор нормализует переводы строк `README.md` до `\n`: иначе на
   CRLF-чекауте не срабатывают регулярные выражения вырезания, и раздел
   «Правило проекта» просачивается на вкладку README — тест это ловит
   (`readme-tabs.test.mjs`, шаг «не должно быть раздела для разработчика»).
5. Проверить соответствие `cordis.patch.yml` ↔ `Config` ↔ `DEFAULTS`.
6. Обновить `README.md`, если изменились возможности или ограничения.
7. Добавить запись в [`decisions.md`](decisions.md) для архитектурных изменений.

## Технический долг

Известные, осознанные долги — фиксируются здесь, чтобы не «чинились» попутно:

| Долг | Где | Комментарий |
|---|---|---|
| Косметика: слипшаяся строка `const key = …;        const value = draft[key];` | `client.js`, `effortControl` | Чисто форматирование; исправлять отдельным диффом |
| Шапка модуля не упоминает `think` | `index.js`, шапка | Описаны только `read`/`web`/`write`; `delegate_inspect`/`think`/`status` не перечислены |
| `index.js` — монолит (~1495 строк) | `index.js` | Логично вынести `verification`, `budget`, `workers`, `prompts`; требует аккуратного рефакторинга с тестами |
| Нет тестов на `client.js` | `client.js` | GUI-рендер и сохранение формы проверяются только вручную |
| Ремонт `edit` не различает несколько вхождений | `expectedContentOf` | См. [`verification.md`](verification.md) → «Ограничения» |
| Сообщение о ремонте сообщает длины, а не позицию расхождения | `settleVerification` | Полезнее был бы фрагмент diff; сейчас агент видит только «Char on disk N vs expected M» |
| `maxJobsPerWorker` и `workerIdleMs` остались настройками, но не управляют жизненным циклом воркера | `index.js`, `cordis.patch.yml`, `client.js` | Либо вернуть поведение, либо пометить поля устаревшими и убрать из формы — сейчас настройка обещает то, чего код не делает (см. D15) |
| Размер пула воркеров — константа, а не настройка | `index.js` → `WORKERS_PER_TASK` | Осознанно: строка настроек не меняется (D25). Если понадобится настраивать, это четыре правки по чек-листу нового поля конфига + `slot` в статусе |
| Тесты `pool.test.mjs` держат воркеров «за руку» | `test/pool.test.mjs` | Стенд ждёт `release` по `childId`; при смене схемы событий стенд надо синхронизировать с харнессом `live-enable` |

## Как оформлять решения

Принципиальные решения (а не очевидные правки) получают запись в
[`decisions.md`](decisions.md) в формате D<номер>:

- **Решено** — что именно;
- **Почему** — аргумент, по возможности со ссылкой на регрессию;
- **Если откатить** — к какой поломке это вернёт.

Ссылки на тесты-маркеры обязательны, если такие есть.

## Чего не делать

- Не менять `node_modules` и профиль DSH (`~/.dsh/profiles/desktop`) — они
  перезаписываются пакетным менеджером.
- Не добавлять зависимостей без отдельной задачи (`schemastery` — единственная).
- Не «оптимизировать» `contextTokensOf`, `pre-step` и фильтр уведомлений без
  прочтения [`decisions.md`](decisions.md).
- Не публиковать пакет: `private: true`, он ставится через `link:`.
